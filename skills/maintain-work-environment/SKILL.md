## 先决定是否值得写入

写入前判断：**这条信息是否改变以后查找、使用、迁移或恢复环境的方法？** 同时检查是否已有等价记录。没有新的长期维护价值就不写；默认不为每次对话、操作成功或任务收尾新增记录。

值得保存的内容：

- 机器与服务的分工、服务作用、正式实例在哪里，以及迁移后旧实例的停用归属。
- 关键配置、持久数据、备份和凭据文件的位置；访问入口、连接依赖、必要端口与管理入口。
- 会影响后续维护的关键选择及简短原因，例如保留公网机作为入口、只有一个正式微信消费者。
- 会改变实际操作的已知限制或恢复注意事项，例如新机有新数据后不能直接启用旧副本；记录必要的兼容版本。
- 用户明确要求长期保留的环境资料。尚未执行的安排只标为计划。

默认不写的内容：

- “测试没问题”“收到”“已确认”、重复状态核对、普通测试通过及逐次验收过程。
- 临时在线状态、耗时、HTTP 状态码、工具数量、命令输出、重试过程及逐步操作流水。
- 已经存在的同义信息，或只为证明助手做过事而追加的日期和证据。
- 不影响后续使用的测试待办列表、推测的故障原因和未确认的部署事实。

例如：服务从公网机迁到无影，应更新机器归属和访问关系；再次确认旧服务已停止，只回答；发现恢复必须先处理数据版本，应保留这一约束；一次健康检查成功，不追加记录。

测试若揭示了持续存在、影响维护的限制，只留下限制及影响。用户另行要求验收报告或故障复盘时，写到对应任务文档，架构清单最多保留必要链接。不把省下的流水转存为另一份知识库记录。

## 查询

1. 先读取权威清单；问题涉及其他资料时，在上述资源范围内检索并读取相关结果。
2. 直接回答机器、服务作用、路径或连接关系。必要时注明资料日期，区分计划和实际部署。
3. 文档不证明此刻在线。只读查询不刷新文档日期，也不为回答位置问题自动连接服务器。
4. 未记录的事实明确说未知，不根据常见安装路径推断实际配置。
5. OpenViking 不可用时，可读取 Git 快照；注明日期及可能过时，不以旧副本覆盖当前知识库。

## 更新

1. 先通过上述写入判断；依据用户明确提供的信息或本次已完成变更，不把计划写成已部署。事实来源影响判断时简短说明，不追加证据流水。
2. 重新读取当前文件，修改对应条目，替换过时状态，合并重复内容；维护当前结构，不累积每日变更日志。只有实质变化才更新日期。
3. 优先精确替换。匹配失败或发生并发修改时重新读取、合并，不用旧全文覆盖新版本。
4. 回读相关内容核对。无实质变化就结束，不为满足流程制造写入；回复以用户关心的结果为主，无需每次强调“已记录”。
5. 有备份或交付需要时再导出 Git 脱敏快照，保留日期及权威 URI，遵循目标仓库要求；不逐条同步，不自动发布博客或维护第二份当前状态。

## 范围

只查询和维护工作环境知识，不扩展为通用对话记忆策略，也不修改 OpenViking 的自动会话保存设置。不包含服务器巡检、定时监控、安装部署或迁移执行。只记录凭据文件位置，不读取或保存密码、Token、私钥、会话凭据或完整私有配置。
