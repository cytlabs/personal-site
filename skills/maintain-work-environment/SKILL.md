# 维护个人工作环境知识库

## 当前资料

- 权威清单：`viking://~/resources/work-environment/architecture.md`。
- 检索范围：`viking://~/resources/work-environment`。
- Git 脱敏快照：`cytlabs/personal-site` 的 `docs/operations/cloud-workspace.md`。
- 博客源稿：该仓库 `posts/cloud-workspace-from-phone.md`，介绍阶段性的架构与工作方式。
- Skill 安装在当前用户空间；客户端须连接同一 OpenViking 用户并支持技能发现与读取。

使用当前客户端的 OpenViking read、find、edit 等工具。工具名称可不同，以当前工具定义为准。URI 中的 ~ 指当前认证用户，不是本地文件目录；没有合适工具时说明限制。

## 查询

1. 先读取权威清单；问题涉及其他资料时，在上述资源范围内检索并读取相关结果。
2. 直接回答机器、服务作用、路径或连接关系，附资料更新时间。计划、已部署和未验证状态分别说明。
3. 文档的上次记录不等于此刻服务在线。读取文档不更新“验证时间”，也不为了回答位置问题自动连接服务器。
4. 未记录的事实明确说未知，不根据常见安装路径推断实际配置。
5. OpenViking 不可用时，可读取可访问的 Git 快照；注明快照日期及可能过时，不以旧副本覆盖当前知识库。

## 更新

1. 依据用户明确提供或确认的信息，或本次已完成操作的结果。仅有迁移计划时，只修改计划，不把它写成已部署。
2. 更新前重新读取当前文件；按变化修改对应服务、机器、路径、依赖和状态，保留其他内容。标明更新日期、依据及仍未验证的部分；用户报告不标为现场核验。
3. 优先使用精确文本替换。匹配失败或出现并发变化时重新读取、合并，不用旧全文覆盖新版本。当前工具不支持编辑时说明限制。
4. 完成后读取相关内容核对，告知改了什么。已有授权范围内的文档维护直接执行。
5. 需要保存 Git 快照时，从更新后的清单导出并脱敏，保留快照日期和权威 URI；遵循目标仓库协作要求。不要自动发布博客或在另一个仓库维护第二份当前状态。

## 范围

只查询和维护架构知识，不包含服务器巡检、定时监控、安装部署或迁移执行；这些操作需要独立任务。保持清单简洁，记录服务、作用、位置、依赖和当前状态，不堆积终端输出。只记录凭据文件的位置，不读取或保存密码、Token、私钥、会话凭据或完整私有配置。
